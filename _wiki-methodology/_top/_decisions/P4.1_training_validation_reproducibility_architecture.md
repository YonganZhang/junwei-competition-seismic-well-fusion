# P4.1 统一训练、验证、复现与可视化架构决策

> 决策日期：2026-07-13  
> 状态：已冻结，供后续 `/goal` 实施  
> 输入：五窗口只读调研、负责人本地审计、官方文档与原始论文  
> 适用范围：六赛道；⑤甜点按七个独立任务 ID 运行。

## 决策摘要

1. 采用**统一外层合同 + 赛道插件**，不强迫分割、分类、回归、时间事件和三维重建共享同一种内部张量。
2. 建立规范模型目录 `_models/<track>/<model_id>.py`；模型文件可替换、可动态发现，赛道 pipeline 只负责数据 adapter 与任务插件。旧赛道 `models/` 暂留兼容 shim，迁移后不得保留两份真源。
3. 冻结独立 test；所有选择在 development 集内通过 group/spatial/time CV 完成。默认争取 5-fold，但独立 group 不足时必须显式降级，禁止拆同井或相邻块凑折数。
4. 选择 **Optuna** 作为可选默认 HPO 后端；简单 baseline 无 Optuna 也必须可运行。当前不整体迁移到 Lightning，也不把 Ray Tune 作为第一阶段强依赖。
5. 全项目采用一个 root seed 派生角色 seed，并保存确定性报告；不承诺跨框架版本、跨平台或 CPU/GPU 的逐 bit 一致。
6. loss、target transform、输出参数化、阈值、metric、搜索空间和 visualizer 全部由 `TaskSpec`/赛道插件显式声明，不能藏在模型文件或训练脚本常量中。
7. 修复共享训练循环的 batch 等权平均问题，统一按样本数或有效标签数聚合。
8. ⑤甜点固定为七个独立任务：储层品质、含油气/有效厚度、产能、见水风险、剩余油/加密井潜力、孔隙度、渗透率。

## 1. 统一模型目录与接口

### 规范目录

```text
_models/
  fault/
  facies/
  property/
  lithofacies/
  sweetspot/
  reconstruction/
```

每个模型文件至少导出：

- `build_model(task_spec, **model_config)`
- `model_id`
- `capabilities()`：任务类型、输入模态、是否支持 missing-mask/uncertainty 等
- 可选 `suggest_hparams(trial, task_spec)`：仅定义该模型自己的搜索空间，不负责读取数据或 test

模型不自行做 split、归一化、test 评估或画图。原赛道模型目录可以提供短期 import shim，但规范模型文件只能有一个 source of truth。

### 外层 envelope

```text
ModelBatch
  inputs: dict[str, Tensor | Array]
  targets: dict[str, Tensor | Array] | None
  input_masks: dict[str, Tensor | Array]
  target_masks: dict[str, Tensor | Array]
  sample_ids: list[str]
  groups: dict[str, list[str]]
  coordinates: dict[str, Tensor | Array]
  metadata: dict

ModelOutput
  raw: dict[str, Tensor | Array]
  transformed: dict[str, Tensor | Array] | None
  uncertainty: dict[str, Tensor | Array] | None
  aux: dict
```

这只是外层字典合同。断层可以返回 3D logits，地震相返回多类 logits，物性返回多个连续头，重建返回 volume；不要求它们共享 shape。

### `TaskSpec` 最低字段

- `track_id`、`task_id`、`task_type`
- 输入模态、目标、单位、标签版本、target mask
- `group_keys`、`spatial_buffer` 或 `time_cutoff`
- target transform / inverse transform
- train loss、推理 transform、threshold/calibration policy
- primary/secondary/guardrail metrics
- HPO search space 与预算
- visualizer ID 与必交付图件

## 2. 数据划分与 test 防火墙

### 统一生命周期

```text
原始数据
  -> 冻结独立 test group/block/time window
  -> development = train + validation 候选
  -> development 内 group/spatial/time CV
  -> 用 pooled OOF 选择配置/阈值/校准
  -> 固定配置，用全部 development 重训
  -> frozen test 只做一次 inference
  -> 归档 test campaign，不再反向改配置
```

每一折都必须只用 fold-train 重拟合：归一化、缺失值处理、类别/正例权重、采样器、特征选择、target transform 和阈值候选。预归一化 HDF5 不能直接作为无泄漏 CV 真源，除非能无损恢复并证明逐折统计。

### 折数规则

`effective_n_splits = min(requested_n_splits, usable_independent_groups)`，同时受类别覆盖、空间 buffer 后有效样本和正例块数量约束。降级必须写进 `split_manifest.json`：

- `requested_n_splits`
- `effective_n_splits`
- `downgrade_reason`
- 每折 group/block/time 边界与 purge/buffer
- 每折类别/标签支持与样本数

不允许的降级：同一母井按样本行随机拆分、相邻 patch 随机 KFold、同一生产事件跨时间切片、同一体派生切片跨集合。

### 各赛道冻结策略

| 赛道 | frozen test | development CV |
|---|---|---|
| 断层 | 独立带标签 volume 优先；不足时完整连续空间块 | buffered 5-fold spatial block；正例块不足则 3-fold/LOBO |
| 地震相 | F3/Penobscot 各自现有连续 test inline | 各数据集独立 buffered 5-fold，不混标签 schema |
| 储层物性 | 母井家族 test | 当前 4-fold LOGO；补足非 test family 后升 5-fold |
| 岩相 | F-5 母井家族 test | 当前 4-fold leave-one-family-out |
| 甜点 | 依目标按母井/空间/时间冻结 | 1/2/6/7 按井或空间；3/4 按井+因果时间；5 按模拟 realization/时刻/空间块 |
| 三维重建 | strict 空间块；conditional 单独作为条件重建报告 | buffered 5-fold K/I block；逐折过滤井约束 |

## 3. 复现与 seed tree

全局配置只暴露一个 `root_seed`，默认项目种子 `2693`；内部由稳定哈希派生：

```text
split_seed
cv_seed
model_seed
loader_seed
sampler_seed
augmentation_seed
hpo_sampler_seed
diagnostic_seed
```

最低实施点：Python `random`、`PYTHONHASHSEED`、NumPy global/Generator、PyTorch CPU/CUDA、DataLoader generator/worker、采样器、增强器、splitter、Optuna sampler。确定性模式优先使用严格失败；若模型包含无法确定化算子，必须记录算子、平台和降级理由。

每次 run 保存：

- Git SHA、dirty 状态、相关源码哈希
- 数据、标签、模型文件与配置哈希
- Python/依赖/OS/CPU/GPU/CUDA/cuDNN/BLAS 信息
- seed tree、确定性开关、warning/非确定算子
- split/fold manifest 与每折预处理统计
- checkpoint（model、optimizer、scheduler、scaler、epoch、RNG state）
- history、OOF/test prediction、metric、visualization、HPO study/trials

复现验收分两级：

- 同环境 deterministic regression：相同 seed 产物/指标在合同允许误差内一致。
- 多 seed 稳健性：最终候选至少 3 个预注册 seed；报告 mean/std/worst，不以挑中的最好 seed 冒充结果。

## 4. 训练控制与自动调参

### 为什么选 Optuna

- 同时适配 sklearn 简单模型和 PyTorch 模型。
- 支持条件搜索空间、TPE、pruner、RDB 恢复与 trial 追踪。
- 侵入性小，不要求重写现有 pipeline。

Ray Tune 只作为未来多机/多 GPU backend；Lightning 的 LR finder 可作为某个神经模型的诊断工具，但不等于“自动找到全局最优学习率”，也不成为统一框架依赖。

### 默认预算

1. `sanity`：8–12 个固定/随机配置，验证搜索空间、方向和异常处理。
2. `pilot`：20–30 个单进程 `TPESampler(seed=hpo_sampler_seed)` trials。
3. `confirm`：top 3 配置 × 3 seeds × 全部有效 folds。
4. 昂贵三维模型先缩小 patch/epoch 做 pilot；正式配置须重新跑完整 CV，不能把 smoke 分数当正式分数。

小组数、噪声大或 batch reducer 未修复前使用 `NopPruner`；有足够可比 trial 后再启用保守 `MedianPruner`。pruner 只读 fold validation 中间指标，不能读 test。

### 目标函数

每个任务只设一个 primary optimization score，并保存：

- fold mean
- fold std
- worst fold
- 失败/越界/校准/结构 guardrail
- 参数量、时长、显存/内存

优先选择“均值不差且 worst fold/稳定性更好”的配置；多目标 Pareto 留作二阶段分析，不在小预算下制造高维选择自由度。

### 学习率、调度器与早停

- 神经网络默认起点：AdamW；LR 用 log 空间搜索。
- scheduler 在 `constant / cosine / ReduceLROnPlateau / OneCycle` 中按赛道限定候选，不全局宣称某个最好。
- early stop 只能监控 fold validation；warmup、patience、min_delta 写入 config。
- 最终 development 重训不再临时切 val；epoch 数从 CV best-epoch 分布预先冻结，例如中位数。

## 5. Loss、最终层与指标决策

### 分类/分割

- 二分类：模型输出 raw logits；`BCEWithLogitsLoss` 或其与 Dice/Focal/Tversky 的组合；sigmoid 只用于推理、指标和可视化。
- 多分类：模型输出 raw logits；CrossEntropy/Focal/CE+Dice/Lovasz 候选；softmax 只用于概率、校准和可视化。
- 类别权重、pos weight 和阈值逐折从 fold-train/OOF 推导，禁止使用 test 分布。

### 连续回归

- MSE 保留为可比基线；默认重点比较 Huber 与 MAE。
- PHIF/SW：训练可用标准化 identity，推理反变换；再比较 sigmoid bounded head。必须报告 raw 指标和越界率，不能静默裁剪。
- KLOGH：主空间为 `log1p`；比较 identity 与保证非负的参数化；同时报告 log 空间、原物理空间和倍数误差。
- 概率回归（Gaussian NLL/quantile）只在 label noise/uncertainty 可被验证时进入二阶段。

### 时间事件/排序

- 见水：固定窗分类用 BCE/Brier/校准；time-to-event 只有在删失和时间轴合同完整后才用 survival loss。
- 产能、剩余油/加密井：MAE/Huber 与 ranking loss 分开比较；Top-K 和 Spearman 不能取代物理误差。

## 6. 可视化合同

通用图只覆盖训练/HPO/CV：loss/LR、fold score、trial history/importance、OOF vs test 分布、seed 稳健性。赛道图必须由保存的 prediction/metric 产物生成，不重新偷跑 test。

| 赛道 | 必交付专属图 |
|---|---|
| 断层 | 输入/GT/probability/TP-FP-FN；三正交视图；PR/阈值；boundary/connected components；三维断层面 |
| 地震相 | 稠密 inline/crossline 真值/预测；error/confidence/entropy；逐类 IoU/F1；混淆与校准 |
| 储层物性 | 真值-预测、残差、逐井深度曲线、空间误差、范围违例、uncertainty coverage |
| 岩相 | 连续井深轨、混淆、逐类 PR/F1、confidence/calibration、embedding、模态消融/缺失模式 |
| 甜点 | 七目标各自图；另有共享空间叠图和目标冲突/Pareto 图，不能只画一个综合甜点热图 |
| 三维重建 | GT/pred/error 三视图、CDF、频谱、变差函数、等值面/体渲染、距井误差；conditional/strict 分开 |

## 7. 运行产物布局

```text
_outputs/runs/<track>/<task_id>/<run_id>/
  run_config.json
  task_spec.json
  seed_report.json
  split_manifest.json
  environment.json
  folds/fold_*/
  oof/
  hpo/
  refit/
  frozen_test/
  metrics/
  visualizations/
  manifest.json
```

`frozen_test/` 只能由单独命令、固定 config 和已完成 refit checkpoint 生成；CV/HPO 命令不得接受 test loader 参数。

## 8. 测试阶梯

1. unit：loss/transform/inverse/mask/metric/seed/reducer 的 shape、finite 和已知答案。
2. contract：模型动态发现、I/O envelope、split 零交叉、test firewall、manifest schema。
3. tiny-overfit：合成或极小 development 样本，证明梯度、loss 和输出能工作。
4. real-data smoke：单 fold、少 epoch、临时目录，验证真实数据全链路。
5. CV：全部有效 folds；保存逐折预处理、checkpoint、OOF 和指标。
6. refit：冻结配置，用全部 development 重训。
7. frozen-test：单独一次 inference，不反向改配置。
8. reproduce：同环境同 seed 回归 + 最终 3 seed 稳健性。

## 9. ⑤甜点七目标可行性门

| 目标 | 当前判断 | 实施前硬门 |
|---|---|---|
| 1 储层品质 | 可做审计代理/排序案例 | 冻结组合规则；构造标签字段不得作为该任务输入；权重敏感性 |
| 2 含油气/有效厚度 | 大概率可做 | 先核对 CPI pay/reservoir flag；若用阈值代理必须标 `proxy` |
| 3 产能 | Volve 生产数据支持，操作定义待冻 | 固定 30/90 天或 PI 等 horizon；井+因果时间切分；禁用未来信息 |
| 4 见水风险 | 生产时序支持，事件定义待冻 | 稳定见水阈值、持续天数、删失、预测 cutoff |
| 5 剩余油/加密井 | 可做模拟案例，真实场标签不足 | 固定 Eclipse/RMS realization、预测/评价时刻；不得称 field truth |
| 6 孔隙度 | 可做 | 独立 PHIF/PHIE label mask、单位/范围/分井审计 |
| 7 渗透率 | 可做 | 独立 KLOGH label mask、`log1p`/反变换/非负性审计 |

缺硬门时输出 `not_feasible.json` 和缺口，不用伪标签凑七个已完成模型。

## 10. 明确不采用

- 不用测试集选 loss、激活、阈值、epoch 或超参数。
- 不为追求“五折”拆同井、随机 patch 或取消空间 buffer。
- 不把所有任务强制成同一 loss、输出激活或图模板。
- 不把自动调参等同于自动得到真理；搜索空间与评价合同仍需人工冻结。
- 不整体重写成 Lightning/Ray，仅为追求框架整齐而增加迁移风险。
- 不在脏 master 上直接合并多个分支；实施必须先做 clean integration worktree 和 commit-range 审计。

## 依据

- PyTorch 官方说明同 seed 也不保证跨版本、平台或 CPU/GPU 完全一致，并给出 DataLoader worker/generator 的复现方法：[Reproducibility](https://docs.pytorch.org/docs/stable/notes/randomness.html)。
- scikit-learn 明确要求 GroupKFold 的独立 group 数至少等于折数：[GroupKFold](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupKFold.html)。
- Optuna 官方提供 TPE、pruner 和中间指标 pruning，但当前 pruner 主要面向单目标：[Efficient Optimization Algorithms](https://optuna.readthedocs.io/en/stable/tutorial/10_key_features/003_efficient_optimization_algorithms.html)。
- 空间结构数据的随机 CV 可产生乐观估计，采用 blocking/buffering 参考 [Roberts et al. 2017](https://doi.org/10.1111/ecog.02881) 与 [Valavi et al. 2019](https://doi.org/10.1111/2041-210X.13107)。
- Equinor 官方将 Volve subsurface data 列为开放数据，用于本项目多数据源案例研究：[Equinor Data Sharing](https://www.equinor.com/energy/data-sharing)。
