# Decision: 六赛道直接基准证据驱动的训练与测试协议修订

## Decision

六赛道现有 Pipeline **保留统一工程骨架，重做科学评估血肉**。当前 Stage-1～4 证明了模型发现、适配、训练、产物、恢复和防火墙能够运行，但不能把短预算 pilot 或已经消费过的 holdout 继续解释为模型能力上限或 fresh-blind 性能。

下一轮实施按以下原则冻结：

1. **标签与样本身份先于模型。** 每个任务先冻结 label version、样本 ID、数据来源、允许输入、开发域、测试身份和 hash；标签不清时 fail-closed。
2. **先划分、后预处理和窗口化。** 测井按母井家族，地震按连续空间块并 purge，动态目标按预测起点和未来 horizon；相邻深度点、重叠 patch、同一地质实现不得随机跨折。
3. **开发、已见 holdout、fresh blind 三层分开。** 开发阶段只看 grouped/spatial/temporal OOF；已见 holdout 只做 regression confirmation；对外泛化结论只能来自从未消费的新井、新区块、新时期或赛事隐藏集。
4. **任务、模态和训练范式分 lane 排名。** classification/regression、P/S、测井单模态/多模态、scratch/pretrained、strict/conditional 都不得混成一个总榜。
5. **十模型要求解释为“十个有审计状态的候选”，不是强行十个数值。** 合法 cell 才能排名；依赖缺失、数据通道不成立、标签无效、超时和数值失败必须保留真实状态。
6. **短预算只做筛选，不做能力结论。** Stage-2/3 的 32/40 updates 或同量级 tree rounds 只能叫 compute-matched pilot；正式榜必须先做学习曲线和固定资源敏感性，再冻结完整预算。
7. **主仓采用一次集成、再开新工作树。** 六份研究报告先按固定顺序进入 `p5-model-benchmark-integration`，跑联合验收并只合并主仓一次；之后六赛道从同一主仓提交新开实施工作树，不在历史 Stage-3 工作树继续漂移。

## 用人话解释现在卡在哪里

不是“模型没有跑”，也不是笼统的“许可证不够”。真正的问题分四类：

- **有些目标没有可监督的真标签。** 例如断层只有正例 stick，没有覆盖审计负例；未标注位置是“不知道”，不是“无断层”。
- **有些测试集已经被看过。** F-5、facies/reconstruction/property 等历史 holdout 已用于 P4/P5 选择或确认，再测一次仍能回归检查，但不再是第一次盲考。
- **有些比较不是同一道题。** 测井单模态与地震+测井、多任务 proxy 与现场真值、P 中心窗口与 S 连续序列、scratch 与 pretrained 不能直接排一个榜。
- **有些训练量只够检查程序。** 32/40 次更新可以证明代码能跑，却不足以说明模型已经训练到位；这就是“骨架有了，血肉还没长好”。

许可证只决定能否复制、再分发某份代码/权重；它**不是科学性能无法排名的统一借口**。例如 TabICLv2 官方代码和回归 checkpoint 已核实为 BSD-3-Clause，当前阻塞是本地 source lock、权重供应与哈希尚未按官方身份重登记。

## 统一训练、验证和测试 SOP

### 1. 数据与标签门

每个目标必须有：

- `label_version`、物理单位、正/负/unlabeled 或连续值定义；
- 不可变 sample ID、well/family/block/time/realization 身份；
- development、known holdout、fresh blind 的明确身份；
- source、label、split、feature、config hash；
- 推理期允许输入白名单，禁止目标派生量或未来信息泄漏。

任何一项不成立，结果进入 `blocked/not_feasible/not_rankable`，不得临时随机拆 20% 补数。

### 2. 划分和交叉验证

- 测井静态任务：外层 mother-well/group CV；侧钻与母井必须同组。
- 地震任务：连续空间块或独立体，边界 purge 至少覆盖 patch 重叠、感受野和空间相关尺度。
- 时间任务：held-well + rolling-origin，训练窗与目标窗按 horizon purge，所有特征时间 `<=t0`。
- 模拟/候选井任务：按地质 realization 和候选空间块隔离。
- 只有 development 外层折用于性能估计；HPO、early stopping、校准、阈值和特征选择在外层 train 内继续分 inner train/validation，不能看外层 validation。

请求五折但独立 group 不足时，应按真实 group 数诚实降折并记录原因，而不是随机深度点补足。

### 3. 随机性与自动调参

- 全局 root seed 保留 `2693`；通过稳定派生函数生成 split、模型、loader 和重复 seed。
- 单 seed 只做 smoke；正式候选至少使用预注册多 seed，报告均值、区间、worst-group 和失败率。
- HPO 只在 inner CV 内运行，冻结搜索空间、trial 数、墙钟、并发和 early-stop 规则；trial 失败不能偷偷换 seed。
- 同时报告固定更新预算和固定墙钟/资源敏感性。不同算法的 `n_estimators`、gradient updates 和 pretrained forward 次数必须分别记录，不能假装单位相同。

### 4. Loss、最后一层和阈值

不存在跨六赛道唯一最优 loss/activation，按任务冻结候选并在 development OOF 选择：

- 多类分类：训练输出 logits；CE/weighted CE 为基线，Dice/Lovász 只在同 split 的预注册消融中比较；推理统一 softmax。
- 二元分割/事件：训练输出 logits；BCE/Focal/Dice 只能在 `valid_label_mask` 上计算；推理 sigmoid，阈值只由 pooled OOF 冻结。
- 连续回归：默认 identity 输出；MAE/Huber/MSE、目标变换和 bounded sigmoid 作为显式候选，不根据 test 选择。始终保存 unclipped prediction，并报告越界率；物理裁剪不能掩盖原始错误。
- 渗透率：训练可用 fold-train 冻结的 log1p 变换，但必须同时报告 log 域和还原后的 mD 指标。
- 见水 survival：与固定窗分类分开建模和排名，保留右删失井。

### 5. 排名规则

只有以下条件同时满足才进入某一 lane 的正式榜：

1. 同一任务、标签版本、输入模态、split、预算和 seed roster；
2. 所有预注册 fold/seed 轴完整，或达到事前冻结的最低完成门；
3. 无 test 调参、无全数据预处理、无重叠样本跨折；
4. 指标包含总体、逐 group、worst-group、置信区间、运行时间和失败/超时；
5. fresh-blind 只执行一次，失败记录保留。

跨 lane 不输出总冠军；可以输出 Pareto 表（性能、稳定性、时间、显存、可部署性），但不能把不同题目的分数混合加权。

## 分阶段实施与停止线

### R0：零训练合同修复

- 修正已发现的 metric/label/source-lock 漂移；
- 生成合法 cell roster 和全套 hash；
- 验证 test API 在开发期不可见；
- 断层、T5、T6/T7、岩相 S 等数据门不满足时保持结构化停止。

### R1：泄漏和语义最小复现

- 每赛道用一个简单模型量化随机 split 与合法 group/spatial/temporal split 的差异；
- 不做 HPO，不访问 fresh blind；
- 证明标签、split、窗口、预处理与指标语义正确。

### R2：学习曲线和 loss/activation 消融

- 固定少数代表模型，至少比较短/中/长三个训练预算；
- loss、输出约束和上下文/模态只做单因素或小型预注册网格；
- 若中长预算仍持续改善，不允许开始正式十模型榜。

### R3：十候选 grouped/spatial CV

- 每个合法 lane 跑同一 fold×seed roster；
- 输出完整 OOF、资源、稳定性、失败状态和专属图；
- 冻结每个 lane 的单一 winner/config/threshold。

### R4：全 development refit + known holdout regression

- 只用于检查集成和历史退化；
- 结果必须带 `fresh_blind=false`，不得重新选模型。

### R5：一次 fresh-blind

- 使用新母井、新空间块、新时期、外场或官方隐藏集；
- 先冻结模型、配置、环境和命令，再一次性推理；
- 只有这一层可以支撑新的对外泛化主张。

## Alternatives Considered

- **把现有 Stage-3/4 数值直接做最终榜。** 放弃：短训练预算和已见 holdout 会把工程 smoke 误写成科学结论。
- **所有赛道统一随机五折。** 放弃：同井相邻深度、相邻地震 patch、重叠时间窗和同一模拟 realization 会泄漏。
- **六赛道共用一个总榜和一个 loss。** 放弃：任务、标签、模态、输出和评价尺度不同。
- **因竞赛非商业就忽略许可。** 放弃：许可不应成为性能借口，但复制和再分发代码/权重仍必须遵守真实条款；可在不复制代码的前提下按论文独立实现。
- **继续在旧工作树追加实现。** 放弃：基线不同会导致 split、合同和依赖漂移，难以统一验收。

## Follow-up

1. 在获得合并授权后，按①断层→②地震相→③物性→④岩相→⑤甜点→⑥重建顺序把六份报告提交引入 `p5-model-benchmark-integration`。
2. 运行联合文档/链接/现有回归门，确认只增加报告与本决策，不改变 Stage-1～4 产物。
3. 将集成分支一次性合并主仓；不要把六个历史工作树分别直合 master。
4. 从新的同一主仓基线创建六个实施工作树，先执行 R0/R1；R2 结果汇总后再批准 R3 长训练。
5. fresh-blind 数据没有落实前，不发布“最终性能榜”或“最佳模型”结论。
