# Decision: 六赛道 P5.2 / protocol R2 学习曲线与单因素消融执行协议

## 决策结论

六赛道从同一已验收基线 `af8c066de0c3fc24fce024abb350b4f2c9e82d9b` 开始 P5.2。R2 的目标不是提前评出十模型冠军，而是先回答三个问题：

1. 当前合法 development 划分是否足以训练和评价；
2. 短/中/长预算是否已经进入平台区；
3. loss、输出参数化、上下文或模态的单因素变化是否值得进入 R3。

六个只读 readiness 预检均返回 `BLOCKING_QUESTIONS=NONE`、`READINESS=READY`，且六个实施工作树仍 clean。这里的 READY 表示“可以按数据门实施 R2”，不表示每条 lane 都能训练：断层三条 lane 当前必须零训练停止，甜点 T4–T7 和岩相 S lane 继续保留真实的 partial/blocked/not-feasible 状态。

## 阶段边界

- **P5.2 / R2**：少量代表模型，三档预算，预注册单因素消融，development-only。
- **P5.3 / R3**：每个合法任务/lane 至少十个有审计状态的候选，在同一 fold × seed roster 上正式比较。
- **P5.4 / R4**：冻结 winner 后全 development refit，只用已经见过的 holdout 做回归确认。
- **P5.5 / R5**：模型、配置、环境和命令全部冻结后，只执行一次真正 fresh-blind。

R2 未达到各赛道预注册 plateau/stopping gate 时，不得启动 R3；不得通过追加预算、删失败 cell、换 seed、重切数据或读取测试集强行过门。

## 六赛道共同不可变合同

### 数据、划分与泄漏防火墙

- 全局 `root_seed=2693`；需要重复试验时统一使用派生 seed `1867973658`、`2137841944`、`3902865753`。
- 先冻结 sample/group/block/time identity 和 split，再做窗口、归一化、缺失处理、类别权重、目标变换、校准或阈值。
- 测井任务按 mother-well/family LOGO；地震任务按连续空间块和 guard/purge；时间目标按 held-well + rolling-origin + horizon purge；重建按固定空间 pseudo-test block。
- 所有统计与可学习预处理只在当前 fold-train 拟合，并保存 fit-row/stats hash；外层 validation 只做一次无偏评价。
- R2 runner 不得提供或接受 physical/frozen/known-holdout/fresh-blind 输入；不得打开 `test.h5`、历史 Stage-4 预测或指标；防火墙失败必须在训练前 fail-closed。

### 训练、loss、输出与预算

- R2 不做 HPO、不做 test 选择、不做 budget-specific tuning，不用 early stopping 偷换固定预算。
- 三档预算必须是同一初始化、同一数据、同一配置的严格嵌套前缀；树轮数、optimizer updates 和预训练推理次数分别记录，不能解释为相同计算量。
- 多类任务训练保存 raw logits，CE 类 loss 直接吃 logits，推理统一 stable softmax；二分类保存 raw logits，推理 sigmoid；回归保存 raw/preactivation 和未裁剪物理域预测。
- loss/output/context/modality 只做预注册单因素或小型非自适应网格；除被考察因素外，fold、seed、模型、预算、样本和预处理必须相同。
- 每个 cell 必须保存状态、配置/代码/数据/split/preprocess hash、实际训练量、资源、有限值检查和评价指标；失败、超时、缺依赖和 blocked 都保留，不补造数值。

### 资源、产物和可复现性

- GPU 只使用共享 `torch-common` 环境并通过 `/mnt/data/yongan-admin-2/.cache/volve-p5/locks/gpu0.lock` 排他锁；tabular 使用现有共享环境，不安装包、不下载权重。
- 可提交证据只含小型源码、测试、JSON/JSONL、README/SOP、manifest 和可重建图；checkpoint、完整预测、大数组、HDF5、cache 和临时文件进入忽略目录。
- 产物不得序列化绝对机器/worktree 路径；manifest 必须绑定输入、代码、配置和全部便携产物 hash。
- 每个赛道只在自己的工作树和 write-owner 内修改，显式暂存，禁止 `git add -A`；恰好一个提交，提交后 clean；禁止 merge、push、删分支或改 Cards 分类。

## 每赛道最低可视化

- 断层：三 lane 覆盖/类别支持/有效 fold 的数据获取曲线或停止图，不能画伪性能曲线。
- 地震相：两数据集分别给学习曲线、seed 分布、full-section seismic/GT/prediction/confidence/error/boundary、confusion、逐类指标和 reliability。
- 物性：每目标/每 lane 的预算曲线、loss×output、逐井深度真值-预测、散点、残差、worst-family、PHIF/SW 越界和 KLOGH 双尺度。
- 岩相：W-P/M-P 分 lane 曲线、fold×seed 热图、固定九类 confusion/PRF/support、calibration、center/window 与 missing-modality 对照；S 只给 not-feasible 证据。
- 甜点：T1–T3 各自预算曲线和消融图；T4–T7 各自状态/data-gate 图或证据，不能合图成综合分。

## 共同验收门

每个赛道提交必须同时满足：

1. 分支、基线、write-owner 和单提交范围正确，提交后 clean；
2. unit/contract 测试覆盖 split-before-preprocess、fold-train-only、cell registry、hash、portable path、重复 cell 和 test firewall；
3. 真实 development R2 入口按预注册矩阵运行，或在科学/资源门失败时输出结构化 blocked/timeout/failure；
4. 结果、summary、可视化 manifest、artifact manifest 和防火墙审计完整；
5. 不输出跨任务/lane winner，不把短预算或已见 holdout 写成 fresh-blind 性能；
6. 负责人独立复跑轻量回归、核对关键结果和产物 hash 后才可集成。

## R3 准入裁决

- R3 是逐任务、逐 lane 准入，不是六赛道一起强行放行。
- 只有标签、split、输入语义、fold×seed 完成度和本文件平台门全部通过的 lane 才能进入至少十候选比较。
- `blocked/not_feasible/not_rankable` 是有效科学结果，不是实现失败；必须保留并明确最小解锁合同。
- R2 若显示中→长仍持续改善，只能冻结 `R3_ALLOWED=false` 并提出下一轮预算研究，不得在本批追加训练追分。
