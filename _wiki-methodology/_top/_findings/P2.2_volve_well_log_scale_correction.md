# 纠正：③④赛道数据量足够，之前finding把"最窄子集"误当"全部数据"

## Local Case

用户质疑 `P2.1_volve_core_data_scale_gap.md` 的结论"数据不够"不对劲，重新核实后确认：之前的调查只查了`Volve_Well_logs.zip`里的`06.LFP`(最终成品测井)和`09.CORE`(实物岩心)这两个最窄的子目录（各自只覆盖3口井，其实是同一口发现井15/9-19的3个分支），就得出"整体数据不足"的结论，完全没检查同一个压缩包里的`02.LWD_EWL`(原始随钻/电缆测井曲线，24口井全覆盖)和`05.PETROPHYSICAL INTERPRETATION`(计算解释测井/CPI，21口井)。

网络核实：Volve油田历史上实际钻井24口。`Volve_Well_logs_pr_WELL.zip`按井分目录，顶层正好24个不同井名文件夹，与历史钻井数吻合。

## Class Pattern

**调查覆盖不全导致结论错误**——只看了压缩包里的一个子目录就下"整体数据量"的结论，没有系统性遍历同一数据源的所有子目录。这跟`share-arch.md §6`的"三类证据必须齐"原则相通：判断数据是否够用，必须遍历完这个数据源实际有哪些子集，不能采样到最窄的子集就代表整体。

## Evidence

- `Volve_Well_logs_pr_WELL.zip`：`unzip -l`确认顶层24个井名目录
- `Volve_Well_logs.zip`：14个数据类型目录，`02.LWD_EWL`(原始测井)24口井全覆盖，`05.PETROPHYSICAL INTERPRETATION`(CPI)21口井
- 301个LAS + 607个DLIS + 20个LIS格式测井文件（DLIS/LIS均为可解析的行业标准格式）

## Impact

**修正③④赛道可行性判断**：不需要依赖岩心化验数据(仍只有约30-47样本，P2.1结论不变)当训练主体，可以用21-24口井的原始/计算解释测井曲线构建训练集——按每口井几百到上千米井段、0.1-0.5m采样估算，合计可达数万至十几万行样本，量级足够支撑基于测井曲线的储层物性/岩相预测模型。岩心数据改为校准/精度验证角色（检验测井曲线经验公式反演孔隙度是否准确），这也是Volve自己`05.PETROPHYSICAL INTERPRETATION`目录CPI产物的标准做法。

**决策点1（③④要不要做）不再需要等军伟拍板**——数据支撑足够，可以直接开工。P2.1里"需军伟决策降级方案"这条门槛作废。

## Prevention Rule (candidate)

判断"数据量是否支撑某任务"时，必须先列出该数据源下所有子目录/子集的清单和覆盖范围，再判断，不能只调查其中一个子集就下整体结论。
