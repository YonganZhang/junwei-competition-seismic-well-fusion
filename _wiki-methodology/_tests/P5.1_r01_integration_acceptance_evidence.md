### Environment-only failure and independent rerun

The first combined run stopped in the facies suite with `OSError: [Errno 28] No space left on device` while writing the second temporary checkpoint. At that moment `/tmp` was on the root filesystem with about 71 MB free, while one generated checkpoint was 57,415,688 bytes. This was not a model, split, metric, or integration failure.

The exact same tests were rerun with `TMPDIR` on `/mnt/data`, which had about 5.3 TB free. The facies suite then passed 67 tests with two expected skips, and the remaining tracks also passed. No source or scientific artifact was edited to obtain the passing rerun.

## Three-layer acceptance evidence

### Command gate

The six registered `p5-r01-*` gates in `_wiki-methodology/_tests/_gates.yml` cover the same accepted suites summarized above. Their YAML and shell syntax were parsed independently after registration. The integrated run produced 290 passes and six explicit skips with exit code 0.

### Live development-data journey

This project is an offline research pipeline, not a web application or continuously running service. The closest valid live journey is therefore the real development-data path:

1. load only the registered development/train container or development-derived bundle;
2. derive immutable sample/group/block identities;
3. create the legal grouped/spatial/temporal split before fitting preprocessing;
4. fit preprocessing and the simple R1 model on fold-train only;
5. score only the legal development validation region, while retaining the deliberately leaky split as a non-rankable diagnostic;
6. save predictions, summaries, figures and artifact hashes under the track-private R01 output directory.

The facies F3/Penobscot, property, lithofacies, sweetspot and reconstruction workers executed this path on real development assets. Fault executed its real label/data gate and stopped the formal lane before training because audited negatives and two legal buffered folds do not exist. No temporary 20% random split or proxy negative was substituted.

### Trace/SSDO audit and downgrade statement

Each track emits a structured R0 contract, R1 summary/results file and artifact manifest or equivalent evidence report. These records expose source/split/config hashes, seed, preprocessing scope, legal versus diagnostic lane, rankability, and test-firewall booleans. The independent regression re-read these saved artifacts and asserted the public contracts.

There is no production request trace, browser DOM, online API transaction or human UI journey to audit in this offline pipeline. That observability layer is explicitly **not applicable** rather than claimed as passed. The accepted SSDO substitute is the data-container access audit plus machine-readable artifact/test-firewall manifests; it is sufficient for this R0/R1 mechanism stage but does not replace a future fresh-blind competition submission trace.

## Stage naming and next gate

To avoid mixing the earlier Stage-1–4 pilot names with the revised protocol R0–R5 names, subsequent work uses:

- **P5.2 / protocol R2**: learning curves and loss/output/context/modality ablations on a small representative roster.
- **P5.3 / protocol R3**: at least ten audited candidates per legal track/lane under the same grouped/spatial/temporal fold × seed roster.
- **P5.4 / protocol R4**: full-development refit plus known-holdout regression only.
- **P5.5 / protocol R5**: one-time genuinely fresh-blind evaluation.

P5.3 must not start merely because R1 code runs. It starts only after P5.2 shows the chosen training budget has reached the pre-registered plateau/stopping condition and each lane has valid labels, splits and input semantics.
